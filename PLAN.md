## 2. Что осталось до «готово к использованию»

Ниже — по приоритетам. Каждый пункт: цель → файлы → критерий готовности → проверка.

### P0 — блокеры реального использования

#### P0.1. Лимит вызовов в сутки (`callLimit`) — ✅ СДЕЛАНО (19.11.2026)
- **Проблема:** поле `settings.callLimit` есть в UI и типах, но нигде не проверяется перед `sendToAgent`. Пользователь думает, что лимит действует.
- **Файлы:** `src/lib/agent-client.ts` (или новый `src/lib/usage.ts`), `src/views/ChatView.vue`.
- **Что сделать:**
  1. Новый стор `src/storage/usage.ts`: хранить счётчик вызовов по `agentId` + дата (UTC-день). IndexedDB-стор `usage` (ключ `agentId`, значение `{agentId, day, count}`) → поднять `DB_VERSION` до 2, добавить стор в `upgrade`.
  2. `canCall(agentId, limit)` → bool; `recordCall(agentId)`; сброс при смене дня.
  3. В `ChatView.send()` до запроса: если `callLimit > 0 && !canCall` → показать ошибку «Дневной лимит N исчерпан», не отправлять.
  4. После успешного ответа — `recordCall`.
- **Критерий:** при `callLimit=1` второй запрос за день блокируется сообщением; на следующий день счётчик обнуляется.
- **Проверка:** юнит-тест `usage.test.ts` (fake-indexeddb): canCall/recordCall/сброс по дате.

#### P0.2. `contextSize` — ✅ УЖЕ РАБОТАЕТ (проверено)
- **Факт:** `sendToAgent` сам применяет `trimHistory(request.history, request.settings.contextSize)` при формировании тела запроса (`agent-client.ts:54`). `ChatView` передаёт полную историю, обрезка происходит в клиенте — корректно.
- **Остаётся:** добавить юнит-тест `trimHistory` (границы: 0, больше длины, порядок), если его нет.
- **Проверка:** тест `agent-client.test.ts` на trimHistory.

#### P0.3. Обработка ошибок сети/HTTP в UI — ✅ СДЕЛАНО (19.11.2026)
- **Проблема:** `AgentClientError` бросается, но `ChatView` показывает сырой `String(e)`. Пользователю нужен понятный текст (401 — ключ, 429 — лимит, timeout, CORS).
- **Файлы:** `src/lib/agent-client.ts`, `src/views/ChatView.vue`.
- **Что сделать:** маппинг кодов статуса в человекочитаемые сообщения; отдельно ловить `fetch` network error (CORS/offline).
- **Критерий:** при 401 видно «Неверный ключ агента», при network — «Агент недоступен (сеть/CORS)».
- **Проверка:** юнит-тест маппера ошибок.

### P1 — целостность данных и UX

#### P1.1. Импорт бэкапа: конфликты и дубликаты
- **Проблема:** `importBackup` делает `putAgent`/`putSession`/`putMessage` вслепую — перезапишет существующие с тем же id, но не предупредит; повторный импорт задвоит сообщения с новыми id? (id приходят из файла — не задвоит, но перезапишет).
- **Файлы:** `src/storage/backup.ts`, `src/views/SessionsView.vue`.
- **Что сделать:** режим импорта — «слиять/заменить» (merge по id, существующие не трогать) + отчёт «добавлено / пропущено / перезаписано». Минимум — предупреждение перед импортом, если в базе уже есть такие id.
- **Критерий:** повторный импорт того же файла не создаёт дублей и сообщает, сколько пропущено.
- **Проверка:** тест `importBackup` merge-логики.

#### P1.2. Валидация настроек агента
- **Проблема:** `contextSize`/`callLimit` принимают отрицательные/NaN значения из формы.
- **Файлы:** `src/views/ConnectionsView.vue`, `src/storage/types.ts`.
- **Что сделать:** clamp `contextSize ≥ 0`, `callLimit ≥ 0`, целые; trim адреса; проверка, что адрес — валидный URL (http/https).
- **Критерий:** нельзя сохранить агента с отрицательным лимитом или пустым/битым адресом.
- **Проверка:** юнит-тест нормализатора настроек.

#### P1.3. Пустой ключ и приватный режим — ✅ СДЕЛАНО (19.11.2026, через describeError)
- **Проблема:** если localStorage недоступен, `sealAgentKey` бросает `missing_seed` — но в UI `ConnectionsView` это показывается сырым текстом ошибки.
- **Файлы:** `src/views/ConnectionsView.vue`, `src/crypto/agent-key-cipher.ts`.
- **Что сделать:** понятное сообщение «Браузер не сохраняет данные (приватный режим) — ключ нельзя сохранить безопасно».
- **Критерий:** пользователь понимает, почему ключ не сохранился.

#### P1.4. Переименование/редактирование агента и сессии

## 4. Риски и ограничения

- **Схема БД v2** (P0.1): `upgrade` должен быть идемпотентным — проверять `objectStoreNames.contains("usage")` перед созданием. Существующие данные не трогаются.
- **Машина:** RAM 956 МБ. `npm run build`/`vitest` идут нормально (проверено). Go-сборки нет — не касается.
- **CORS:** агент должен отдавать CORS-заголовки для браузерного POST; это ограничение клиента, в UI надо явно сказать в ошибке.
- **Безопасность:** ключи только в `enc:v1:`, в бэкап не попадают (тест есть). Не логировать расшифрованный ключ.
