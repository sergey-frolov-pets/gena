# Полный рефакторинг Gena

_2026-11-21. План по фактическому коду ветки `main`. Цель — стабильность, меньше ошибок, возможность добавлять функции без разрастания одного файла. Поведение для пользователя на этапах 0–4 не меняется._

## 0. Диагноз

Gena — статическое SPA (Vue 3 + Vite + TypeScript + IndexedDB). Бэкенда нет. Три транспорта: `http_json`, `openai`, `pico_ws`. Состояние чата живёт в модульных `ref` (`src/lib/store.ts`) и в `localStorage` (черновик, pending-ход, вкладки).

| Файл | Строк | Роль |
|---|---:|---|
| `src/views/ChatView.vue` | ~4813 | скрипт ~1700 + scoped-стили ~1500 + глобальные стили |
| `src/lib/transports/pico-ws.ts` | ~838 | WebSocket, resume, ping, стрим, отмена |
| `src/views/ConnectionsView.vue` | ~461 | форма агента |
| `src/views/SessionsView.vue` | ~444 | бэкап, очистка, список |
| `src/lib/store.ts` | ~366 | CRUD поверх IndexedDB |
| `src/style.css` | ~155 | общая тема |

Чистая логика уже вынесена удачно: `composer`, `queue`, `errors`, `ui-blocks`, `backup`, транспорты с тестами. Дальше ломается не стек, а граница между UI и жизненным циклом хода.

### Откуда берутся ошибки

1. **Один компонент владеет всем ходом.** Отправка, очередь, черновик, pending в `localStorage`, стрим, мысли, вложения, sheet истории, вкладки диалогов, клавиатура, visualViewport — в `ChatView.vue`. Любая новая кнопка рискует задеть `send()`, `recover` и восстановление после `pagehide`.
2. **Два источника правды о «ходе в полёте».** IndexedDB-очередь (`storage/queue.ts`), pending в `localStorage`, `busy`/`typing`/`streamingText` в компоненте и сокет внутри `pico-ws.ts`. Рассинхрон даёт повторную отправку или потерянный ответ.
3. **Транспорты неравны, а UI этого не знает явно.** Картинки умеет только `pico_ws`. Отмена, `turn.resume`, `message.delete` — тоже. Ветки `if (protocol)` размазаны по вью.
4. **Стор — синглтон.** `agents`/`sessions`/`messages` — модульные `ref`. Тесты и будущие экраны делят одно состояние. Гонка `loadMessages` при быстром переключении сессий не изолирована.
5. **Схема IndexedDB и бэкапа растёт полями.** `protocol`, `config`, `serverId`, вложения, `ui` добавлялись совместимо, но миграции не названы отдельным слоем: `upgrade` в `db.ts` и `parseBackup` легко разъедутся.
6. **Девять локалей копируют ключи вручную.** Английский — источник истины, но нет генерации типов из одного словаря: новый ключ легко забыть в `hi`/`ar`.
7. **UI уже плотный.** Три равноправные вкладки (подключения / чат / сессии), иконки без подписи, бренд в шапке, переключатель языка и темы, плашки версии, сети, лимита и хода. На телефоне шапка и док спорят за высоту.

Старые планы (`PLAN.md`, `docs/plan-chat-port-20261119.md`, `docs/plan-plugins-v2.md`, `docs/stability-20261120.md`) описывают фичи. Этот документ их не отменяет: он задаёт каркас, в который эти фичи должны садиться.

## 1. Принципы

- **Поведение сначала фиксируем тестами, потом двигаем код.** Рефакторинг без нового контракта агента.
- **Один ход — один автомат.** Состояния: `idle → queued → sending → streaming → settling → idle`, плюс `reconnecting` и `failed`. Переходы только из чистых функций, UI подписывается.
- **Компонент рисует, модуль решает.** Vue-файл не пишет в IndexedDB и не открывает сокет.
- **Возможности транспорта — таблица, не `if` по строке протокола.** `supports: { media, stream, resume, cancel, tools }`.
- **Схема данных версионируется в одном месте.** `DB_VERSION` и `BACKUP_VERSION` меняются вместе с функцией миграции и тестом «старый снимок открывается».
- **Новая фича = папка, а не абзац в `ChatView`.** Плагин UI, вложение, протокол подключаются реестром.
- **Минимальный UI = меньше постоянных контролов, не меньше функций.** Редкие действия уходят в одно меню «ещё».

Не делаем: новый бэкенд, смену Vue, Pinia ради Pinia, переписывание криптоконверта `enc:v1`, объединение трёх протоколов в один.

## 2. Целевая структура

```
src/
  domain/           # типы Agent, Session, Message, Turn — без Vue и без idb
  persistence/      # db, миграции, backup, usage, queue (сейчас storage/)
  session/          # фасад стора: load/save, отмена устаревшего loadMessages
  turn/             # автомат хода, очередь, pending, лимит вызовов
  transports/       # как сейчас + capabilities
  plugins/          # реестр карточек gena-ui (рендерер на плагин)
  ui/
    shell/          # шапка из одной строки, меню
    chat/           # лента, пузырь, мысли, композер, вложения
    connections/    # лист настроек агента
    library/        # история и бэкап (бывший Sessions)
  i18n/
```

Импорты наружу из папки идут через `index.ts`. `ChatView.vue` после разрезания не содержит стилей длиннее самого шаблона: общие токены остаются в `style.css`.

## 3. Этапы

Каждый этап — отдельный PR, зелёные `typecheck`, `vitest`, `build`. Откат этапа не требует отката данных пользователя.

### Этап 0. Страховка (без смены поведения)

Цель: иметь тесты, которые поймают регрессию переноса.

- Зафиксировать сценарии хода в тестах, которые уже почти есть, и добавить недостающие чистые кейсы:
  - обрыв сокета посреди стрима → `reconnecting`, не `failed`, пока попытки не кончились;
  - `pagehide` с непустым композером → черновик читается обратно;
  - очередь из двух реплик: вторая не уходит, пока первая не `settling`;
  - смена сессии во время `loadMessages` не подмешивает чужие сообщения;
  - импорт бэкапа версии 1 в текущую схему.
- Вынести из `ChatView` константы (`FEED_WINDOW`, ключи `localStorage`) в `turn/keys.ts`, чтобы тесты не импортировали `.vue`.

Критерий: падение теста указывает на сценарий, а не на строку шаблона.

### Этап 1. Автомат хода

Новый модуль `src/turn/machine.ts`: чистая функция `(state, event) → state`. События: `enqueue`, `start`, `delta`, `notice`, `socketClosed`, `retry`, `resume`, `complete`, `fail`, `stop`.

Свести в него:

- флаги `busy`, `typing`, `stopping`, `streamingText`, `turnStartedAt` — производные от состояния, не отдельные `ref`, которые можно забыть сбросить;
- pending (`readPending` / `writePending` в `ChatView`) и IndexedDB-очередь — очередь одна, pending только снимок головы очереди на случай убийства вкладки;
- лимит `canCall` проверяется в `start`, не в шаблоне.

`pico-ws.ts` остаётся транспортом: он шлёт события (`onDelta`, `onNotice`, close), автомат решает, ошибка это или `reconnecting`. Тайминги 0.5→15 с и потолок 6 попыток переезжают в таблицу рядом с автоматом и покрываются тестом без WebSocket.

Критерий: `ChatView` вызывает `turn.send` / `turn.stop` и рисует `turn.status`. Повторная отправка того же текста после возврата на вкладку идемпотентна по `clientTurnId`.

### Этап 2. Разрезать `ChatView`

Порядок выноса — от листьев к корню, каждый PR компилируется:

| Компонент | Забирает из ChatView |
|---|---|
| `Composer.vue` | textarea, Enter/Shift из `composer.ts`, черновик, высота строк |
| `AttachmentTray.vue` | картинки, документы, ошибки вложений, лайтбокс |
| `MessageList.vue` | окно 80 сообщений, «показать раньше», мысли, роли |
| `HistorySheet.vue` | список сессий, пин, переименование, поиск |
| `SessionTabs.vue` | вкладки и `localStorage` их порядка |
| `ChatView.vue` | сборка: агент, сессия, ход, эти блоки |

Стили компонента живут рядом с ним. Токены (отступы, радиус, цвет статуса, высота дока) — в `style.css` как переменные, чтобы мобильный safe-area не копировался.

Критерий: `ChatView.vue` меньше ~400 строк скрипта. Ни один новый файл не импортирует приватные функции другого Vue-файла.

### Этап 3. Сессии и стор

- `loadMessages(sessionId)` хранит поколение запроса: ответ для старого id отбрасывается.
- Запись сообщения идёт через один `appendMessage`; оптимистичное сообщение и серверный `serverId` — поля одного объекта, а не вторая копия в pending.
- `selectedSessionIds` остаётся во вью «библиотека», не в глобальном сторе.
- Оценка квоты (`navigator.storage.estimate`) — один сервис `persistence/quota.ts`: порог «мало места» до `QuotaExceededError`, как в `docs/stability-20261120.md`. Осиротевшие blob-URL чистятся там же при закрытии лайтбокса и смене сессии.

Критерий: тест с двумя перекрывающимися `loadMessages` оставляет на экране сообщения последней сессии.

### Этап 4. Транспорты и схема

- `TransportCapabilities` на каждом транспорте. Композер спрашивает `caps.media`, а не `protocol === "pico_ws"`. Кнопка вложения скрыта, если транспорт не умеет картинки; документ текстом по-прежнему доступен везде, где уходит `history`.
- `cancel` — метод транспорта. У `http_json` / `openai` он только абортит `fetch`. У `pico_ws` шлёт кадр отмены и абортит локально. Автомат в обоих случаях переходит в `idle` и пишет одну и ту же ошибку «остановлено», если сервер не подтвердил.
- Миграции IndexedDB: функция `migrate(oldVersion)` с тестом на fake-indexeddb для каждой версии, которая есть у живых пользователей (сейчас v2). Новое поле — необязательное, чтение через нормализатор `normalizeAgent` / `normalizeMessage` (уже начато в `agent-form`).
- Бэкап: `parseBackup` вызывает те же нормализаторы. Ключ по-прежнему не экспортируется.

Критерий: добавление четвёртого протокола = новый файл транспорта + строка в реестре, без правок ленты.

### Этап 5. Плагины UI

Сейчас блок `gena-ui` парсится в `ui-blocks.ts`, а набор плагинов — множество строк в `plugins/types.ts`.

- Реестр: `pluginId → { validate(data), Component }`. Неизвестный id — текст резюме, как сейчас.
- Карточка не пишет в стор сама: действие зовёт `turn.sendSilent(text)` и помечает `blockId+actionId`, чтобы двойной тап не слал дважды (уже заложено в `docs/plan-plugins-v2.md`).
- Лимиты размера (`MAX_BLOCK_BYTES`, `MAX_ITEMS`) остаются в одном модуле и тестируются до рендера.

Критерий: новый плагин — папка `plugins/<id>/` с тестом валидатора. `ChatView` не меняется.

### Этап 6. Ошибки и локали

- Все пользовательские сбои — код из `errors.ts` и ключ i18n. Сырой `String(e)` в ленту не попадает; техническая строка пишется в кольцо `error-log` (50 записей уже есть).
- Тип ключей вывести из `en`: `type Key = LeafPaths<typeof en>`. Сборка падает, если `ru`/`ar`/… пропустили ключ. Скрипт `tmp/` и `scripts/patch_i18n_queue.py` после этого не нужен.
- Одна плашка статуса в чате: сеть, лимит, ход, обновление версии — приоритет, а не стопка. Обновление версии важнее сети, ошибка хода важнее подсказки.

Критерий: в шаблонах нет конкатенации текста ошибки с `e.message`.

### Этап 7. Минимальный интерфейс

Смотри раздел 4. Делать после этапа 2, иначе перестановка кнопок снова раздует `ChatView`.

## 4. UI: меньше постоянного, то же самое по делу

Сейчас три вкладки верхнего уровня и шапка с брендом, языком, темой и установкой PWA. Чат — единственный частый экран. Подключения и бэкап редкие.

### Каркас

```
┌──────────────────────────────────────┐
│ ‹ диалоги    Имя агента         ···  │  одна строка 44px
├──────────────────────────────────────┤
│                                      │
│            лента                     │
│                                      │
├──────────────────────────────────────┤
│ [+]  сообщение…              (↑)     │  одна строка, растёт вверх
└──────────────────────────────────────┘
```

- **Убрать постоянные вкладки.** «Чат» — это корень. «Подключения» и «Сессии» открываются из меню `···` и из `‹ диалоги`. Глубокие ссылки не нужны: маршрута нет и не появляется.
- **Шапка без бренда на экране чата.** Имя продукта остаётся на пустом состоянии (нет агентов) и в меню. Иконка, подпись «AI chat», переключатели языка и темы из шапки уходят в лист «Настройки».
- **Один агент виден как заголовок**, смена — тап по заголовку (список агентов). Отдельный экран мастера нужен только для создания и правки ключа.
- **Композер — одна строка.** Слева «+» (фото, файл, быстрые фразы). Справа отправка, во время хода она становится «стоп». Диктовка и речь — внутри «+», не отдельные иконки в доке. Поле растёт вверх до 6 строк, дальше внутренний скролл.
- **Вкладки диалогов** остаются только если их больше одного; одна сессия — без полосы табов. История — тот же sheet, что уже есть.
- **Одна статусная строка** над композером: «печатает», «связь прервалась — переподключаюсь», «лимит 20/20», «нет сети». Цвет один (приглушённый), ошибка — единственный красный акцент на экране.
- **Действия сообщения по долгому нажатию и по «⋯» у пузыря**, а не постоянная hover-группа на каждой реплике. На десктопе hover можно оставить, но не добавлять новые кнопки в ряд.
- **Пустое состояние** — одно предложение и две кнопки: «подключить агента», «открыть недавний диалог». Без стартовой сетки карточек.
- **Плотность.** Тап-цели ≥ 44px, но горизонтальные поля 16px, между пузырями 8px. Вторичный текст (время, модель) показывается по тапу на пузырь, не под каждым сообщением.
- **Темы.** Светлая и тёмная остаются. Переключатель один, в настройках, плюс `prefers-color-scheme`, если пользователь ещё не выбирал.
- **Язык.** Автоопределение `navigator.language`, список — в настройках, не в шапке каждого экрана. RTL для арабского не трогаем.

### Что не прятать

Отправка, стоп, вложение, список диалогов, текст ошибки хода. Всё остальное терпит один лишний тап.

### Проверка UI

На 390×844 и на ширине ≥ 1024: отправить текст, остановить ход, приложить фото (если протокол умеет), открыть историю, сменить агента, дойти до настроек языка. Клавиатура не перекрывает композер (`visualViewport` уже учитывается — сохранить).

## 5. Масштабирование функций

| Хочу добавить | Куда | Чего не трогать |
|---|---|---|
| Новый протокол агента | `transports/<name>.ts` + реестр | ленту, бэкап ключей |
| Карточку в ответе | `plugins/<id>/` | парсер ограждения, автомат хода |
| Поле настроек агента | `AgentSettings` + нормализатор + форма | `ChatView` |
| Команду композера | пункт меню «+» | разметку дока |
| Хранимое поле сообщения | необязательное поле + миграция + тест бэкапа vN | старые записи без поля |

Правило ревью: PR, который добавляет больше 200 строк в существующий Vue-файл, дробится до слияния.

## 6. Порядок и риски

Порядок: 0 → 1 → 2 → 7 (оболочка) параллельно с 3 → 4 → 5 → 6. Этап 7 не начинать до разрезания `ChatView`, иначе стили переедут дважды.

| Риск | Как снять |
|---|---|
| Тихий регресс resume на телефоне | Этап 0 фиксирует переходы автомата; ручная проверка из `stability-20261120.md` остаётся на этапе 1 |
| Потеря черновика при переносе ключей `localStorage` | Имена ключей не менять в этапе 2; смена формата — отдельный мигратор с тестом |
| Двойная отправка при слиянии pending и очереди | Идемпотентность по `clientTurnId` в этапе 1, до удаления старого pending |
| Большой PR со стилями | Этап 2 дробить по компонентам; стили переезжают вместе со своим блоком |
| Плагин ломает старый клиент | Неизвестный `plugin` и лишний JSON по-прежнему показываются как текст резюме |

Критерий конца рефакторинга:

- новый протокол и новый UI-плагин добавляются без правки `ChatView.vue`;
- у хода один статус, который можно напечатать в тесте;
- `typecheck`, тесты и сборка зелёные;
- на телефоне и десктопе сценарии из раздела 4 проходятся без второй шапки и без стопки плашек.
