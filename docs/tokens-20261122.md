# Справочник подстановок и перенос между устройствами (2026-11-22)

## Зачем

В чате встречаются значения, которые не должны уходить агенту и лежать в
истории открытым текстом: суммы, адреса, номера. Решение — справочник: короткое
имя `⟦имя⟧` прячет значение за токеном. Агент получает **только токены**;
настоящие значения остаются на устройстве (в памяти интерфейса) и подставляются
обратно в ленте чата.

## Решения Сергея (22.11.2026)

1. **Откуда записи.** Ручной ввод в Gena есть: имя, значение, варианты, заметка.
   Импорт файла — дополнение, а не единственный путь.
2. **Что считается «защищённой сессией».** Та, которую человек **явно** перевёл
   в режим токенов. Автоматика (сработала подстановка — значит защищена) не
   используется.
3. **Шифрование на устройстве.** Значения запечатаны ключом устройства
   (seed → HKDF → AES-GCM), без пароля при каждом открытии. Отдельный пароль —
   только у файла переноса.
4. **Объём.** Фундамент и авто-подстановка перед отправкой — в этой итерации;
   морфологический словарь — следующим шагом (варианты падежей пока задаются
   руками в `variants`).

## Формат токена

- Канон: `⟦имя⟧` (U+27E6 / U+27E7). В обычном тексте почти не встречается,
  markdown и LaTeX не ломает, санитайзер пропускает как текст.
- На вводе терпим `[[имя]]` и `{{имя}}` — приводятся к канону.
- Имя: 1–80 символов, без скобок и переводов строк, уникально без учёта регистра.

## Движок подстановки

`src/lib/tokens/substitute.ts`, только стандартные средства браузера.

- Многословные значения («вклад ВТБ в Альфа-Банке»), регистр не важен.
- Границы слова соблюдаются: «ВТБ» не вырезается из середины другого слова.
- Самое длинное совпадение выигрывает; уже стоящие токены не оборачиваются
  повторно — повторный проход идемпотентен.
- Разные написания (падежи, сокращения, обратный порядок слов) — в `variants`
  записи. Морфология не угадывается: лучше явный список, чем ложные замены.
- Значения короче 2 символов и значения со скобками токена не участвуют.

## Хранение

- IndexedDB `gena`, версия **4**, стор `tokens` (индекс по имени — уникальный).
- `TokenRecord.sealedValue` = `enc:tk1:<iv>.<cipher>`, HKDF-соль `gena.token.v1`,
  additionalData = id записи. Смена сида устройства или чужой id → не расшифровать.
- В памяти значения открыты (иначе подстановку не сделать); после перезагрузки
  читаются из базы и расшифровываются ключом устройства.
- `Session.tokenMode` — флаг хранения: включение переписывает историю значениями →
  токенами, выключение возвращает значения обратно. На отправку флаг не влияет:
  агент получает токены в любом диалоге.

## Что уходит агенту, что лежит на диске

| Куда | Что |
|---|---|
| История (IndexedDB), режим токенов | токены |
| История (IndexedDB), обычный диалог | как набрано; при отправке всё равно заменяется на токены |
| Очередь реплик (IndexedDB) | токены |
| Незавершённый ход (`gena.chat.pending`) | токены |
| Агент (тело запроса, история контекста, текст документов) | **только токены** |
| Лента на экране | значения, по кнопке «Показать токены» — токены |

Правило проверяется в одном месте — `src/lib/tokens/outgoing.ts` (`forAgent`,
`historyForAgent`). Если справочник не прочитан или часть записей не
расшифровывается, отправка блокируется: лучше отказ, чем значение в запросе.

## Файл переноса

Один файл, один пароль, без слотов устройств и сервера.

```
{ "format": "gena.tokens", "version": 1, "createdAt": 1732..., "count": 12,
  "kdf": { "name": "PBKDF2-SHA256", "iterations": 210000, "salt": "b64" },
  "cipher": { "name": "AES-GCM", "iv": "b64" },
  "payload": "<base64 AES-GCM>" }
```

- Ключ: PBKDF2-SHA256 (210 000 итераций, соль 16 байт) → AES-GCM-256.
- Пароль вводится руками, минимум **12** символов, повторяется при экспорте.
  Мастер-пароль сейфа не годится: файл может уехать почтой.
- Параметры KDF привязаны к шифротексту через AAD — подменить число итераций
  или соль незаметно не получится.
- В файл попадают только записи: имя, значение, варианты, заметка, даты.
  Ни id, ни слотов, ни резервных кодов, ни TOTP.
- Ошибки разделены: `bad_file`, `unsupported_version`, `wrong_password`,
  `password_too_short`, `no_entries`.

## Импорт и совпадения

- Совпадение — одинаковое имя без учёта регистра.
- Если совпадений нет — записи добавляются сразу.
- Если есть — интерфейс предлагает три пути: «Заменить все», «Оставить мои»,
  «Спросить по каждой» (список с выбором на каждую запись).
- Заменённая запись получает id прежней: уникальный индекс по имени не ломается.

## Подсказка по мере набора (22.11.2026, вечер)

`src/lib/tokens/trigger.ts` — как только в поле появляется открывающая скобка
`⟦` (или терпимые `[[`, `{{`), над композером показываются имена справочника.
Набранное после скобки фильтрует список: совпадения по подстроке, начинающиеся
с запроса — выше. Выбор подставляет канон `⟦имя⟧` вместо набранного фрагмента,
каретка встаёт сразу за закрывающей скобкой, пробел добавляется только при
слипании со следующим словом. `Escape` закрывает подсказку. Вне защищённого
диалога подсказка не появляется.

## Уточнения 22.11.2026, вечер

1. **Режим токенов — отдельный тип сессии**, а не просто флаг хранения.
   При нажатии кнопки «Режим токенов» у диалога меняется вид: фон панели
   подкрашивается акцентом, в фон вписан полупрозрачный замок, на вкладке
   и в списке сессий стоит замок. Выход из режима возвращает обычный вид
   и переписывает историю обратно значениями.
2. **Панель режима над полем ввода.** В защищённом диалоге над композером
   появляется строка кнопок: «Справочник», «Вставить токен», «Показать
   токены/значения», «Выйти из режима». На телефоне со свёрнутым вводом
   в доке висит кнопка-замок, открывающая поле ввода.
3. **Вставка токена по курсору** — `src/lib/tokens/insert.ts`
   (`insertTokenAt`): канон `⟦имя⟧` дописывается в позицию каретки, пробелы
   добавляются только при слипании со словом, повторный токен не дублируется,
   кривой `selectionStart` прижимается к границам текста.
4. **Падежи — вариант «а»: скачиваемый морфологический словарь.** Словарь
   лежит отдельным файлом на устройстве (скачивается один раз, офлайн),
   по нему строятся падежные формы значений. Пока справочник не скачан или
   слово в нём не найдено — работает прежний путь: формы берутся из `variants`,
   которые человек вписал руками. Морфология никогда не подменяет собой
   ручные варианты: приоритет у явных `variants`.

## Морфологический словарь: вариант «а» реализован (22.11.2026, вечер)

- **Ассет.** `public/morph/ru-morph-v1.json` — **11 239 лемм** (9 381 существительное,
  1 858 прилагательных), 3,34 МиБ JSON (~400 КиБ при сжатии на отдаче). Собран
  `scripts/gen-morph.py` из pymorphy3 / OpenCorpora (CC BY-SA 3.0) + wordfreq top-40 000
  (CC BY-SA 4.0) + слова из документов репозитория и рабочего корпуса. Структурная
  проверка файла — `node scripts/check-morph.mjs` (формат, версия, порядок падежей,
  число форм, контрольные леммы).
- **Формат** — `src/lib/tokens/morph/format.ts`: `gena.morph` v1, падежи `nomn…loct`;
  у существительного 12 форм (6 падежей × 2 числа), у прилагательного 24 (6 × 3 рода
  + 6 множественного); `null` — форма дефектной парадигмы. Файл проверяется целиком
  при скачивании: чужой формат, версия или порядок падежей → отказ, падежи не строятся.
- **Хранение** — база `gena` версии **5**, стор `morph` (одна запись `ru`). Словарь
  скачивается один раз и дальше работает офлайн; удаление возвращает прежнее поведение.
- **Загрузка** — `loader.ts`: потоковое чтение с прогрессом, лимит 32 МБ, коды ошибок
  `network | http | bad_file | too_big | aborted`.
- **Движок** — `analyze.ts`. Индекс «словоформа → разборы» строится один раз (с алиасами
  «ё» → «е»). Склоняются только слова из словаря. Не склоняются: имя собственное не
  первым словом и всё, что стоит после предлога — «улица Ленина» → «улицы Ленина»,
  «вклад ВТБ в Альфа-Банке» → «вклада ВТБ в Альфа-Банке». Из множественного числа
  единственное не строится («деньги» → «денег», а не «деньгой»). Винительный мужского
  неодушевлённого совпадает с именительным, поэтому «текущий счёт» не даёт
  «текущего счёт». Регистр переносится, включая дефисные части («Альфа-Банк» →
  «Альфа-Банка»).
- **Приоритет.** Явные `variants` записи идут первыми, словарь дописывает свои формы
  в конец (`service.withDeclensions`), дубли отбрасываются. Дополнительно добавляются
  написания без «ё»: «счёт» и «счет» совпадают в обе стороны.
- **Интерфейс.** В «Справочнике» блок «Морфологический словарь»: статус, объём,
  скачать / обновить / удалить, полоса прогресса. `loadMorph()` вызывается и при старте
  чата, чтобы падежи работали до захода в справочник.
- **Проверки.** `vue-tsc --noEmit` — 0 ошибок; vitest **416/416** (+16 движок, +7 формат,
  +7 сервис); `vite build` ок (733 КБ); `check_code.py` 13 файлов — 0 проблем;
  `node scripts/check-morph.mjs` — OK.
- **Осталось.** Серверный скилл, который сам разбирает токены (сейчас раскрытие на
  клиенте); проверка словаря в CI (пока запускается руками перед коммитом).

## Решения Сергея по UX (22.11.2026, ночь) — реализовано

1. **Плашка снизу поля, а не меню у выделения.** Выделил фрагмент в поле ввода —
   под полем появляется строка: «фрагмент» + действие. Всплывающих меню у текста нет.
2. **Подтверждение — первый раз обязательно, дальше не спрашиваем.** Первая отправка
   в токеновом диалоге показывает плашку «Агенту уйдут только токены. Замен: N» с
   кнопками «Отправить» / «Отмена». После подтверждения в диалоге ставится
   `tokenSendAck`, и дальше отправка идёт без вопроса. Галочки «не спрашивать» нет —
   решение и так запоминается на диалог.
3. **«Показать токены/значения» — на диалог.** `Session.tokenView: "tokens"` (отсутствие
   = значения), сохраняется в IndexedDB вместе с диалогом, при переключении диалога
   вид переключается вместе с ним. Глобальной настройки нет.
4. **Известное значение — без карточки, но с подтверждением.** Если выделенный
   фрагмент совпадает со значением или вариантом записи, плашка сразу предлагает
   `⟦имя⟧`; по кнопке — `ConfirmModal` «Заменить выделенный текст на ⟦имя⟧?», затем
   замена. Имя не спрашивается. Неизвестный фрагмент — имя вводится в самой плашке
   и создаётся запись (`saveToken`), после чего фрагмент заменяется токеном.

**Код.** `src/lib/tokens/selection.ts` (`normalizeFragment`, `findSelectionEntry`,
`replaceRange`) + 7 тестов; `Session.tokenView` / `tokenSendAck` в
`src/storage/types.ts`; `setSessionTokenView` / `ackTokenSend` в `src/lib/store.ts`;
в `ChatView.vue` — плашка подтверждения, плашка выделения, `send()` → `sendNow()`
с гейтом, `@select` на поле.

**Проверки.** `vue-tsc --noEmit` — 0; vitest **423/423** (50 файлов); `vite build` — ок;
`check_code.py` — 0 проблем.

## Имена токенов: категории и нумерация (2026-11-22, вечер)

Правило Сергея: имя всегда с номером — `имя1`, а если `имя1` занято, то `имя2`;
для типовых значений есть свои основы: `компания1`, `сумма1`, `телефон1` и т. д.

- **Нумерация с единицы.** `numberedName()` в `src/lib/tokens/selection.ts` перебирает
  `base1`, `base2`, … до 99, затем добавляет время. Имя без номера больше не предлагается:
  `цена` → `цена1`, занятое `цена1` → `цена2`.
- **Справочник основ** — `NAME_BASES` в том же файле (единственное место правки):
  `имя` (запасное), `сумма`, `телефон`, `компания`, `счёт`, `дата`, `почта`.
  В плашке они показываются чипами-подсказками.
- **Как выбирается основа.** Сначала первое и второе значимое слово выделения без
  предлогов и организационно-правовых форм (`ООО`, `АО`, `ИП`…). Затем категория по виду
  значения (`categoryBase`):
  | Вид | Основа |
  |---|---|
  | `ivan@example.com` | `почта` |
  | `12.03.2027`, `12/03/27` | `дата` |
  | `+7 916 123-45-67` (≥10 цифр, только цифры и разделители) | `телефон` |
  | есть `₽`, `руб`, `$`, `€`, `¥` | `сумма` |
  | есть `ООО`/`АО`/`ИП`/`ЗАО`/`ПАО` | `компания` |
  | только цифры без слов | `сумма` |
  В конце всегда `имя`.
- **Лимит** — 3 подсказки в плашке (в коде до 4, показываем 3 после исключения введённого).
- Тесты: `src/lib/tokens/selection.test.ts` — 15 (нумерация, категории, занятые имена, лимит).

## Несколько вхождений одного значения (2026-11-22, вечер)

- После первой замены плашка не закрывается: она показывает `⟦токен⟧`, стрелки
  «‹ 2 / 5 ›» по остальным вхождениям, «Заменить» для текущего и «Заменить все N».
- Вхождения ищутся в поле ввода и в **текстовых сообщениях открытого диалога**
  (в ответах агента — только в режиме токенов, иначе плашка пишет, что замена недоступна).
- Заблокированы: совпадение внутри существующего токена `⟦…⟧` и совпадение внутри слова
  («счёт» в «расчёт»); они считаются в подсказке, но не заменяются.
- Пробелы во фрагменте считаются любыми пробельными (неразрывный пробел, двойные).
  Регистр при поиске не важен, кроме записей с флагом `caseSensitive` (см. раздел про

## Регистр — свойство токена, а не диалога и не серии (2026-11-22, ночь)

## Исходные формы в поле и падеж в ленте, подтверждение «Заменить все» (2026-11-23, день)

Ответы Сергея на вопросы: **1** — формы показывать в поле ввода, **2** — «Заменить все»

  форму: «вклада ВТБ» и «вкладу ВТБ» рядом больше не превращаются оба в «вклад ВТБ».

- **Лента: падеж по предлогу.** Новый `src/lib/tokens/context-case.ts`: карта «предлог → падеж»

- **«Заменить все».** Кнопка показывается только в режиме токенов (`tokenSessionNow`),
