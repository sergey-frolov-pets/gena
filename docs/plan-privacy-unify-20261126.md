# Защищённый режим: автоскрытие как настоящие токены + фикс зависания композера

_План, 2026-11-26. Только план, код не менялся. Прочитано: `src/lib/privacy/{detect,mask}.ts`,
`src/lib/tokens/{registry,highlight,name-bases}.ts`, `src/lib/composer.ts`,
`src/views/ChatView.vue` (264–420, 2205–2262, 3293–3330, 5115–5130, CSS 6903–7030)._

## 1. Диагноз разрыва

- `mask.ts:3–8` — скобки `[…]` выбраны **намеренно**, чтобы маска не выглядела как токен без записи в справочнике. Это и есть корень: маска задумана как «не токен».
- `detect.ts:8–9` — «значение хранится для показа в панели, в журнал и бэкап не попадает». После `maskText` (`mask.ts:35–53`) значение теряется безвозвратно, раскрывать «показом значений» нечего.
- `ChatView.vue:327–340` (`onPrivacyMask`) переписывает `draft` целиком; единственная связь с исходником — `privacyUndoText` (откат всего разом и только до следующей правки, `watch(draft)` на 296–305 его обнуляет).
- `highlight.ts:16–22` знает два вида: `token` (справочник) и `offer` (значение справочника открытым текстом, `findOfferSpans`, `ChatView.vue:409`). Находок детектора в подложке нет вовсе: у панели и поля разные источники правды.
- `registry.ts:31–45` — у `TokenEntry` нет признака происхождения; `saveToken` (183–220) после каждой записи делает `loadTokens()` с расшифровкой всех записей — пакетное создание N авто-токенов дорогое.
- `name-bases.ts:65–75` (`nextBaseName`) даёт `сумма1`, `сумма2`, а в требованиях — `сумма`, `сумма 2`. Нужно выбрать одну схему (вопрос 2).
- Отклонение сейчас только по типу (галочки → `types` в `maskText`) и «Не скрывать» на весь текст (`privacyDismissed` = текст целиком, сбрасывается любой правкой).

## 2. Целевая архитектура

**Владение.** Значение хранит только registry (шифрованно). Токен в тексте — только `⟦имя⟧`. Находка детектора — **кандидат**: в памяти, ничего не пишет в БД.

**Модель.**
- `TokenEntry` / `TokenRecord`: + `origin?: "manual" | "auto"` (по умолчанию manual) и `kind?: FindingType`.
- Авто-токен всегда сессионный: `sessionId = текущий диалог`, `shared: false` → `tokenInSession` и `entriesForSession` работают без изменений.

**Жизненный цикл.**
1. **Ввод.** Детектор на debounce 250 мс (как сейчас, `ChatView.vue:281`) → список кандидатов. Кандидаты попадают в подложку как третий вид сегмента `candidate` (пунктирная подсветка акцентным цветом) и в панель. Registry не трогаем.
2. **Фиксация** (кандидат → токен) — только в трёх точках, не на нажатие клавиши:
   а) кнопка «Скрыть» в панели (весь набор или одна находка);
   б) перед отправкой — все неотклонённые кандидаты включённых типов (если Сергей это подтвердит, вопрос 1);
   в) явное «В токен» по находке в облачке.
   Фиксация = чистый планировщик `planAutoTokens(text, findings, types, entries)` → `{ text, create[], reuse[] }` + одна пакетная запись `saveTokens([...])` (один `loadTokens()` в конце).
3. **Имена.** Основа — `MASK_LABEL[kind]` (`сумма`, `карта`, `телефон`, `почта`, `счёт`, `дата`). Дедуп по значению: нормализованное значение (`digitsOnly` для карт, счетов и телефонов, схлопнутые пробелы для сумм, lower для почты) уже есть у записи этой сессии или у общей → берём её имя. Иначе — следующий свободный номер с учётом **всех** имён справочника (ручные не перекрываются; `saveToken` и так бросает `name_duplicate`).
4. **Показ.** «Показать значения» идёт через `dialogTokenLookup` (`ChatView.vue:774`) → registry, поэтому авто-токены раскрываются без отдельного кода. Подложка и лента: `HighlightSegment` + `auto?: boolean` (по `origin` записи), класс `is-auto` → свой цвет, геометрия общая.
5. **Отправка и история.** Без изменений: `forAgent` / `historyForAgent` отдают `⟦сумма⟧`, история хранит токены, `markChatHtml` раскрывает по registry.
6. **Отказ.**
   - От кандидата: «Не скрывать» на находке → значение попадает в набор `declinedValues` диалога (в памяти и в черновике диалога, без самого значения: храним хеш), больше не предлагается. Галочки типов остаются.
   - От авто-токена: «Вернуть текст» → все `⟦имя⟧` в черновике заменяются значением; если токен не встречается в сообщениях диалога — `removeToken`. Встречается в отправленной истории → значение остаётся (иначе история перестанет раскрываться), токен помечается «не использовать дальше» (вопрос 4).
   - «Вернуть всё» (бывший `onPrivacyUndo`) = откат текста + удаление записей, созданных этой фиксацией (храним id пакета).
7. **Правка и удаление.** Правка значения в режиме показа — как у ручных токенов (разрыв токена в `display.ts`), без спецкейса. Уборка сирот: при очистке поля, отправке, удалении диалога, а также при `loadTokens` удаляются авто-записи сессии, которых нет ни в черновике, ни в сообщениях. Для удалённой сессии — все её авто-записи.

## 4. Миграция и обратная совместимость

- Значений у старых `[сумма]` нет нигде (`detect.ts:8–9`) → превратить их в настоящие токены **невозможно**. Варианты: а) оставить как есть; б) оставить текст, но подсвечивать как «скрыто без значения» (серым, без раскрытия).
- **Рекомендация: б**, только для ленты защищённых диалогов (там же, где `markChatHtml`). Данные не трогаем, миграции БД нет.
- Записи справочника без `origin` = manual, поле опциональное → старые бэкапы и `transfer` читаются без изменений.
- Новые бэкапы: авто-токены экспортируются с `origin: "auto"`; старое приложение их прочитает как обычные (поле игнорируется).

## 5. Фикс зависания композера (2 → 3 строки)

**Причина — подтверждаю.**
- `ChatView.vue:2256–2261`: `composerLayout` — чистая функция от числа строк.
- CSS: в `pair` (6994–7030) правая группа `flex-direction: row` (микрофон/молния + отправка в ряд), в `column` (6947–6975) — столбец кнопок 26 px. Значит, при 2→3 правая группа **сужается**, поле **расширяется**.
- `autoGrow` (3293–3330) меряет по **текущей** ширине поля (`measureWidth = clientWidth + scrollbar`). Текст, которому при ширине `pair` нужно 3 строки, при ширине `column` влезает в 2 → `pair` → поле сужается → 3 → `column` → …
- `composerObserver` (5121–5127) реагирует на смену `clientWidth` textarea → снова `autoGrow` → цикл не гаснет. Флаг `measuringComposer` защищает только сам замер, не смену раскладки.
- Та же ловушка возможна на 1↔2: в `row` кнопки в ряд с **обеих** сторон, а в `pair` левая становится столбцом и поле шире.

**Вариант 1 (минимальный, хотфикс).** Ширина боковых групп не зависит от раскладки: `min-width` у `.chat-panel__composer-actions` (и `-lead`) = ширина её самого широкого состояния (константа из `sizes.ts`). Ширина textarea постоянна → цикла нет. Один CSS-блок, тестов на логику не надо. Минус: в `column` справа от узкой колонки ~40–60 px пустоты, поле не использует ширину, которую освободили.

**Вариант 2 (правильный).** Раскладка как неподвижная точка, замер по ширине **кандидата**, а не по текущей:
```
для L из [1, 2, 3+]:
  w = boxInner − sideWidth(layoutFor(L))   // ширины сторон — константы sizes.ts
  need = linesAt(w)                         // measureComposerContent(el, w, pad) — уже умеет ширину
  если need ≤ L или L = 3+: вернуть (layoutFor(L), need)
```
Чистая функция `resolveComposerLayout(measure, widths)` в `lib/composer.ts` (до 3 замеров на скрытом зеркале, без перекладки DOM). Наблюдатель — на `.chat-panel__composer-box` (ширина контейнера), а не на textarea: смена раскладки больше не триггерит пересчёт. Результат детерминирован, колебаний нет ни на 2↔3, ни на 1↔2, ширина не теряется.

**Рекомендация:** вариант 2, отдельным коммитом M0 до всего остального (2–3 ч + тест на функцию). Если нужно прямо сейчас — вариант 1 как хотфикс (15 мин), затем заменить вариантом 2.

## 6. Открытые вопросы Сергею

1. **Фиксация при отправке:** неподтверждённые находки включённых типов скрывать автоматически при «Отправить», или только по кнопке «Скрыть»? (Определяет, может ли значение уйти агенту открытым текстом.)
2. **Имена:** `сумма`, `сумма 2` (как в задаче) или `сумма1`, `сумма2` (как сейчас в `name-bases.ts` у ручных)? Одна схема на оба механизма.
3. **Область авто-токена:** только этот диалог (рекомендую) или общий справочник? (Меняет дедуп и уборку.)
4. **Отказ от авто-токена, который уже ушёл в отправленном сообщении:** сохранять значение, чтобы история раскрывалась (рекомендую), или удалять, и тогда в истории останется `⟦сумма⟧` без значения?
5. **Старые `[сумма]`:** оставить как есть или подсвечивать как «скрыто без значения»?
