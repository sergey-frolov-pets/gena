## 1. Зачем и что именно

Цель: внутри чата Gena показывать не только текст, но и интерактивные карточки —
задачи Озадчника с кнопками «готово / удалить / перенести», будильники (cron) с
«выключить / включить / удалить», доску беклога, просмотр markdown-заметки.

Требования:

1. **Ноль изменений на сервере.** Pico-канал не трогаем.
2. **Безопасно.** Никакого исполнения чужого JS/HTML: только данные + встроенные компоненты.
3. **Совместимо.** Старый клиент видит понятный текст, новый — карточку.
4. **Расширяемо.** Новый плагин = JSON-описание, без правки ядра.

## 2. Контракт: UI-блок в сообщении

Агент присылает обычный текст, в конце — блок в ограждении:

````
Задачи на сегодня, 7 штук. Три просрочены.

```gena-ui
{"v":1,"plugin":"ozadachnik.tasks","title":"Задачи","data":{"items":[
  {"id":"a1","title":"Дописать план плагинов","status":"in_progress","badges":["важно"],"due":"20.11"},
  {"id":"a2","title":"Ротация GitHub-токена","status":"todo","due":"21.11"}
]},"actions":[
  {"id":"done","label":"Готово","scope":"item","style":"primary","send":"задача {id} выполнена"},
  {"id":"del","label":"Удалить","scope":"item","style":"danger","confirm":true,"send":"удали задачу {id}"},
  {"id":"refresh","label":"Обновить","scope":"view","hidden":true,"send":"[ui:ozadachnik.tasks]"}
]}
```
````

Правила:

- Блок **всегда последний** и **один** на сообщение (два — второй игнорируется, в лог).
- **`content` в хранилище не меняется.** Блок вырезается только на выдаче: единый хелпер
  `textOnly(content)` обязаны использовать копирование, TTS, экспорт диалога, поиск и
  **история, которая уходит агенту** (иначе агент получает собственный JSON и жжёт токены).
- Блок рендерится **только когда ход завершён** (`message.update`-стрим может содержать
  недописанный JSON): условие — сообщение не последнее в стриме и не `liveStreaming`.
- `v` — версия схемы, сейчас `1`. Неизвестная версия → блок показывается как текст.
- Общий размер блока ≤ 64 КБ, `items` ≤ 200, строка ≤ 2 000 символов.
- Невалидный JSON / неизвестный `plugin` / провал схемы → **тихий fallback**: сообщение
  рендерится как обычный текст (в консоль — одна запись через `error-log.ts`). Чат никогда не ломается.

### Декларативная схема (то, что умеет `GenericView`)

```
data: {
  view: "list" | "table" | "board" | "card" | "markdown",
  items?: Item[],            // list / table / board
  groups?: {key,label,items}[]  // board (колонки)
  markdown?: string,         // markdown / card
  empty?: string             // текст пустого состояния
}

Item: {
  id, title, subtitle?, status?, due?,
  badges?: string[], meta?: {label,value}[],
  checked?: boolean, disabled?: boolean,
  url?: string                // внешняя ссылка (https/http только)
}

Action: {
  id, label, scope: "item"|"view",
  style?: "primary"|"ghost"|"danger",
  send: string,               // шаблон: {id} {title} {status} {value}
  confirm?: boolean,          // модалка ConfirmModal
  hidden?: boolean,           // реплику не показывать в ленте
  optimistic?: "remove"|"check"|"disable"   // локальный отклик до ответа агента
}
```

Этого хватает на 90% случаев: список задач, доска с колонками, таблица, заметка.

### Нативные плагины (v2, не в этой итерации)

`registry.ts` сразу поддерживает компонент на плагин (`{ meta, component? }`), но в v1
все три плагина рендерит `GenericView` с пресетом оформления (`preset: "tasks" | "board" | "notes"`).
Критерий перехода на нативный компонент: нужен layout, который схемой не выражается
(например, календарная сетка). Тогда плагин = отдельный файл, схема остаётся прежней.

## 4. Как работает действие

1. Пользователь жмёт «Готово» на задаче `a1`.
2. `confirm` есть → `ConfirmModal`; нет → сразу.
3. Шаблон `"задача {id} выполнена"` → `"задача a1 выполнена"` (подстановка только из данных блока,
   значения дополнительно экранируются и обрезаются).
4. `optimistic: "check"` → карточка мгновенно помечается, кнопки гаснут (`disabled`).
5. Отправка идёт тем же путём, что обычная реплика (`enqueue`/`dispatch`), но с `hidden: true`:
   в ленте не появляется, вместо неё мини-плашка «Отправлено агенту…» (гаснет 4 с).
   Для этого в `store.ts` появляется **один** helper `sendSilent(agentId, sessionId, text)`:
   `dispatch` без `appendMessage`, без роста `messageCount`, но с `recordCall` и очередью.
6. Агент отвечает новым сообщением с обновлённым блоком. Старая карточка остаётся как снимок,
   `disabled` снимается через 30 с, если ответа не было (и плашка «не подтвердилось»).

Почему не патчить сообщение на месте: `message.update` приходит только от сервера, а
перезапись истории в IndexedDB ломает инвариант «история = то, что реально было».

## 5. Серверная часть — это скилл, не Go

Плагины получают данные от агента, значит нужен контракт на моей стороне:
новый скилл `skills/gena-ui/SKILL.md`.

- `[ui:ozadachnik.tasks]` → агент вызывает `tasks_list` и печатает блок.
- `[ui:backlog.board]` → `backlog.py ls` → блок с колонками.
- `[ui:notes.list]`, `[ui:notes.doc <path>]` → чтение `vault/*.md` → блок `markdown`.
- `[ui:cron.list]` → `cron list` → список будильников с действиями «выключить/удалить».

Скилл содержит: таблицу соответствия `plugin → инструменты`, шаблоны блоков, лимиты
(не больше 200 строк, обрезать длинные заголовки), правило «блок последним».
Именно это делает систему расширяемой: новый плагин = запись в таблице + запись в `registry.ts`.

## 7. Риски и как снимаем

| Риск | Что делаем |
|---|---|
| Старый клиент показывает JSON-простыню | блок короткий (≤ 64 КБ), в тексте всегда есть человеческое резюме до блока; версия в `docs/plugins.md` |
| Модель «забывает» формат и печатает кривой JSON | валидация с fallback + `serializeBlock()` в скилле; при ошибке агент получает подсказку-шаблон |
| Модель вставляет HTML/скрипт в данные | рендер текстовыми нодами, `markdown.ts` экранирует до разбора, ссылки только http/https |
| Действия спамят агента | `hidden` + дебаунс 1.5 с на `id`+`action`, дневной лимит вызовов уже есть (P0.1) |
| Блок раздувает контекст агента | в историю агента уходит текст без блока (обрезка в `pico-ws`/`agent-client`) — экономия токенов |
| Плагин-компонент падает | `errorCaptured` в `PluginHost` → «Не удалось показать карточку» + текст |

## 8. Чего в v1 нет (осознанно)

- Загрузка сторонних плагинов с сервера и iframe-песочница — только после стабилизации контракта.
- Двусторонние формы с вводом (input/textarea) — нужна отдельная модель валидации.
- Стриминг внутри карточки (живое обновление без нового сообщения).
- Серверный `kind: "ui"` — когда появится машина под Go-сборку, контракт переиспользуется 1:1
  (`payload` блока = тот же JSON).
