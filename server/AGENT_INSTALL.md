# Установка Gena server: задание для агента

Серверная часть Gena лежит в этом же репозитории — `github.com/sergey-frolov-pets/gena`,
каталог `server/`. Отдельный репозиторий `GenaClaw` к серверу отношения не имеет:
это форк агента, там серверного кода нет.

В установке участвуют двое, и у каждого своя часть.

| Кто | Что делает |
|---|---|
| **Человек** | Даёт доступ к серверу, называет домен, решает «наружу или нет», принимает адрес и токен |
| **Агент** | Проверяет окружение, ставит службу, поднимает HTTPS, проверяет и возвращает результат |

---

## Часть 1. Что требуется от человека (до старта)

Агент без этих ответов не начинает — иначе поставит не туда и откроет не то.

1. **Доступ.** SSH-ключ и `sudo` на том сервере, где сервер и должен жить. Если агент
   работает прямо на этом хосте — просто подтвердить, что ставить можно здесь.
2. **Домен.** Имя или поддомен для доступа (например `gena.example.ru`) либо явное
   «без домена, только локально». Если домен есть — возможность добавить A-запись
   в DNS: Caddy/Nginx без неё сертификат не получит.
3. **Публикация.** «Публиковать наружу: да/нет». При «нет» порт наружу не открывается
   вообще, доступ — только с этого хоста или через SSH-туннель.
4. **Порт.** По умолчанию 8787. Если он занят — согласие на 8788 (агент сообщит, если
   придётся взять другой).
5. **Куда вернуть токен.** Чат с агентом или другой согласованный канал. Токен —
   единственный ключ к диалогам, в открытые каналы и репозитории он не попадает.
6. **Границы.** Подтверждение, что трогать существующие сайты, прокси и службы нельзя.

## Часть 2. Задание агенту (копировать целиком)

```text
Задача: поставить Gena server на этот сервер и вернуть мне адрес и токен.

Сначала сверься со мной — без ответов не начинай:
- SSH и sudo на сервере у тебя есть;
- домен для доступа: <вписать домен или «без домена»>;
- публиковать наружу: да/нет;
- порт: 8787, если занят — 8788 и сообщи;
- токен пришли в чат, когда всё будет готово.
Если чего-то не хватает или ответ расходится с тем, что ты видишь на сервере — спроси,
дальше не иди.

1. Разведка: uname -a, free -m, df -h /, go version, docker --version,
   ss -ltnp | grep -E '8787|8788' — свободен ли порт и кем занят.
2. Поставь службу:
   git clone https://github.com/sergey-frolov-pets/gena
   cd gena/server && sudo bash install.sh
   Go нет, но есть Docker — собери образ по server/README.md.
   Нет ни Go, ни Docker — поставь Go из репозитория дистрибутива и повтори.
3. Проверь службу: systemctl status gena-server,
   curl -s 127.0.0.1:8787/api/health — в ответе должно быть "ok":true.
   Отдельно проверь, что токен работает:
   curl -s -H "Authorization: Bearer $(cat /etc/gena-server/token)" 127.0.0.1:8787/api/sessions
4. Доступ снаружи — только если «публиковать наружу: да»: HTTPS через Caddy или Nginx
   на 127.0.0.1:8787 с сертификатом на указанный домен. Без домена порт не открывай,
   оставь локально и скажи об этом. Существующие сайты и их сертификаты не трогай.
5. Не открывай порт без токена, не меняй другие службы, не правь чужие конфиги прокси.
6. Верни мне пять пунктов: адрес (с https://, если настроен прокси), токен из
   /etc/gena-server/token, версию из /api/health, путь к данным и команду перезапуска.
```

## Часть 3. Критерии готовности

Агент докладывает «готово» только когда всё ниже — правда:

- [ ] `systemctl is-active gena-server` → `active`
- [ ] `curl -s 127.0.0.1:8787/api/health` → `"ok":true` и номер версии
- [ ] запрос `/api/sessions` с токеном отвечает 200, без токена — 401
- [ ] данные лежат в `/var/lib/gena-server`, владелец `gena`, каталог `0750`
- [ ] токен в `/etc/gena-server/token`, права `0600`
- [ ] если домен есть: `https://<домен>/api/health` отвечает `"ok":true`, сертификат валиден
- [ ] если домена нет: 8787 слушает только `127.0.0.1` (проверить `ss -ltnp`)
- [ ] чужие службы и конфиги прокси не изменились (`systemctl --failed` пуст)

## Часть 4. Что агент возвращает человеку

```text
Адрес:        https://gena.example.ru   (или http://127.0.0.1:8787 — только локально)
Токен:        <из /etc/gena-server/token>
Версия:       <version из /api/health>
Данные:       /var/lib/gena-server
Перезапуск:   sudo systemctl restart gena-server
Порт:         8787 (или 8788, если 8787 был занят)
Прокси:       Caddy, конфиг /etc/caddy/Caddyfile, блок gena.example.ru
```

Дальше человек вставляет адрес и токен в Gena: «Подключения» → «Добавить сервер Gena»
→ «Проверить» → «Сохранить».

## Частые осечки

| Ситуация | Что делать |
|---|---|
| Порт 8787 занят | `GENA_PORT=8788 sudo bash install.sh`, сказать человеку |
| Нет systemd (контейнер) | Docker по `server/README.md` |
| Нет домена | Оставить на `127.0.0.1:8787`, доступ через SSH-туннель, не открывать порт |
| 80/443 заняты другим сайтом | Новый сайт в существующем прокси отдельным блоком, чужие блоки не править |
| Нет Go и Docker | `apt install golang-go` (или аналог), затем повторить установку |
| Служба падает: `permission denied` на `/etc/gena-server/token` | Токен должен принадлежать `gena` (`chown gena:gena /etc/gena-server/token`, каталог `gena:gena 0750`); в `install.sh` это уже исправлено |
| Нужно слушать только локально | `GENA_ADDR=127.0.0.1:8787 sudo bash install.sh` (или поправить `-addr` в юните и `daemon-reload`) |
| Уже стоит старая служба | Не сносить: `curl /api/health`, сравнить версию, обновить бинарник и перезапустить |
| `systemctl reload caddy` падает: `dial tcp 127.0.0.1:2019: connection refused` | В Caddyfile стоит `admin off`. Без admin-API reload невозможен, помогает только полный `restart` (обрыв на секунду). Правится строкой `admin 127.0.0.1:2019` в глобальном блоке — один раз, дальше reload работает |
| Let's Encrypt отдаёт `NXDOMAIN looking up A` сразу после создания записи | Публичный DNS уже отвечает, но резолверы LE кэшируют негативный ответ. Ничего не менять: подождать 2–5 минут или `systemctl restart caddy` — вторая попытка проходит |

### HTTPS через существующий Caddy

Служба слушает только `127.0.0.1`, снаружи её публикует прокси. Готовый блок (добавить
в конец `/etc/caddy/Caddyfile`, домен заменить на свой):

```
api.example.com {
	encode gzip zstd

	reverse_proxy 127.0.0.1:8787 {
		transport http {
			read_timeout 600s
			write_timeout 600s
		}
	}
}
```

Порядок: `cp Caddyfile Caddyfile.bak` → правка → `caddy validate --config /etc/caddy/Caddyfile`
→ `systemctl reload caddy` (или `restart`, если admin выключен) → проверить
`curl https://api.example.com/api/health`. Таймауты 600 с нужны из-за длинных ответов
модели и загрузки файлов.

## Ручная установка (без агента)

1. `git clone https://github.com/sergey-frolov-pets/gena`
2. `cd gena/server && sudo bash install.sh`
3. Скрипт напечатает адрес и токен — сохранить их.
4. В Gena: «Подключения» → «Добавить сервер Gena» → адрес и токен → «Проверить» → «Сохранить».
5. Кнопка «＋ сессия» в чате создаёт диалог на сервере.

Docker: `docker build -t gena-server . && docker run -d -p 8787:8787 -v gena-data:/data -e GENA_TOKEN=... gena-server`

Данные: `/var/lib/gena-server`. Бэкап: `tar czf gena.tgz -C /var/lib gena-server`.
